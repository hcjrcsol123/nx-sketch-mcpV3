# V3 开发清单：参考 PRT 逆向参数化与 UG11 建模脚本

2026-11-08 本次工作仅规划文档，不开发、不启动 NX；本轮及后续均不执行 Git、不计算文件/目录/模型 hash。32 项主任务的实时状态只记在 [V3-state](V3-state.md)，本清单仅定义范围和验收；初始化均未开始。续做、授权和证据复用按 [V3-stage-handoff](V3-stage-handoff.md)。本清单由高级 AI 起草，须由另一高级 AI 实例独立评审。

## 1. 用户目标与交付边界

V3 面向通用机械零件，主要流程是读取由 STEP 导入 NX 后保存的参考 PRT，借助已有 MCP 建模能力生成独立参数件，具有原生草图、尺寸、实体特征及可追溯的特征历史；约定工程尺寸和关系真正可编辑，再从统一建模计划导出 **UG11 独立建模脚本**。用户已指定 [tests/外球叉.prt](../tests/外球叉.prt) 为代表样件；2026-11-08 规划初始化时，其是否为导入体、有无既有历史及保存版本尚未经 NX 读取，后续 T01/T02 结论只记入台账及所链接证据。输出示例为新路径下的 `外球叉_参数化.prt`，原件只读。

主流程：**参考 PRT → NX2506 参数 PRT → UG11 参数 PRT**。参考只读，明确选择参考实体及模型状态；输出使用新名称、新路径，不覆盖参考。原 STEP 如有则保留溯源，无原 STEP 不阻塞以参考 PRT 为基准的工作；不新增必需 STEP 导入器，也不重新开发已有导入功能。

UG11 是本会话确定的最低版本目标，“低版本”不泛指任意 NX。脚本在 UG11 空白零件中按计划逐步创建原生草图、驱动尺寸及实体特征，导航器保留建模历史，保存后的尺寸仍可编辑；不需要 UG11 MCP、不需要打开 NX2506 新版本 PRT，不依赖参考 PRT、录制 Tag 或 UI 回放。逐步建模不是 UI 动画要求。

普通 STEP 导入体不能唯一确定原设计历史。重建允许采用另一套经确认的参数化特征顺序，但必须覆盖整件几何与约定的全部工程驱动关系；不能用导入体、链接体、固定曲线、无使用者表达式或整体缩放冒充全参数。

**以已指定的真实机械件作为整件验收对象，简单块体只作烟测。** 2026-11-08 规划初始化时，样件已提供但尚未做 NX 几何分析，尺寸意图也未确认；实时进展见台账。不能从“外球叉”名称推断球面、叉耳、孔槽或任何实际特征。识别器不按文件名或固定尺寸硬编码，支持域由实测能力定义，不保证任意 PRT 全自动。样件中实际存在且交付要求保留的部位均为核心范围；未覆盖的几何或复杂曲面为明确阻塞，不能删面、抹平细节、以部分成功或小块体替代整件交付。

几何数值必须来自 NX 原生读取，不凭名称、截图或外观猜测。产品以自动读取、识别和计划生成为主，歧义和设计意图再由人工确认；不能要求用户手写整套 IR 代替逆向。手写 IR 仅用于前期独立烟测。

## 3. 样件范围、参数账本与能力缺口

T01 取得代表性参考 PRT，确认选定实体、单位/坐标、是否含多个目标实体、关键基准及交付范围。读取文件或当前已打开模型的状态必须明确，脏状态不得被静默保存或与磁盘版混用。只读分析不得通过创建 Section 等动作暗中修改参考件。

按几何/操作族调查主体与截面、局部增料、减料、重复/对称关系及过渡，不把任意零件套入专用模板。孔槽、腔/开口、凸台/筋、圆角/倒角/拔模等均仅在**实际读取证明样件包含**时建对应任务；主体不强制为回转体。每区须列来源面/边、候选特征、尺寸/关系、工具路线和未解释区域。

不预设 200 面、20 特征等产品上限。读取预算、运行时间、内存与建模规模限度按实际样件测量后确定；触限是该样件尚未完成的原因，不是删除几何的依据。现有工具字段上限仍逐调用遵守。

参数账本覆盖全部约定工程驱动项，而非仅少数关键尺寸：每项区分独立尺寸、关联公式、派生量、固定基准及其理由；定义单位、初值、编辑区间、组合约束和越界策略。孔位置/孔距、壁厚、同轴/对称/等距等若为设计意图须真关联；从几何无法唯一推断时要求人工确认。

对复杂曲面不能武断转成常量控制点后称全参数；应说明拟用原生特征和控制参数如何解释该区域。识别未定、曲面误差无法界定或工程意图待确认，均列为样件阻塞，不先全拒绝复杂件再以简单件替代。

缺口登记采用 **T04.a、T04.b…** 等稳定子任务，正式开发发现后才创建：一个受限几何/API问题、一个后端或共享模块、唯一文件所有者、具体反例与验收。识别问题也可用 T13.a 等归属其分区任务；禁止一个“补齐复杂零件全部功能”子任务。

每个必需缺口先评估：直接调用 → 薄适配 → 几何及关系等价的参数化组合 → 最小新增能力。确认后写明依赖与双版本覆盖；必需缺口未关闭不得释放整件执行/验收。分析及缺口状态以台账和证据为准，不能虚构缺口已关闭或实际能力已满足。

## 4. 统一计划与验收定义

路线：只读参考快照 → 分区和候选/人工确认 → 参数账本与版本化 IR → 现有 MCP 调用编排生成 NX2506 新件；同一 IR → UG11 能力 profile/脚本生成 → UG11 空白件逐步重建。

IR 最少包括参考快照编号/路径/版本、选体、单位/刚体坐标变换、稳定分区/特征逻辑 ID、基准、草图与实体操作、参数公式及约束、依赖 DAG、来源几何、歧义确认、版本能力需求和未关闭项。按改动记录及必要原生读取核实适用性，不计算 hash，也不把元数据当内容一致证明；脚本运行不读取源 PRT。

跨会话重定位靠逻辑 ID、父特征和几何语义的唯一性校验；Tag/JID/面边序号仅为当前会话临时信息。失配或多解停止，不猜测。未知操作、循环依赖、量纲错误、遗漏区域或待确认意图不生成“整件可执行”计划。

### 建模前的特征历史引导

V3 在生成关联建模计划时，要帮助 AI 回答一个设计问题：用户将来修改一个尺寸时，哪些几何应一起变化，哪些要能单独修改？计划中有共享截面或重复布局时，向用户说明涉及哪些特征、判断依据、预计可省哪类构造，以及采用后哪些编辑会联动。原生特征数的估计须给出计数对象，实际收益须由采用该路线后生成的模型核实。

- 草图能表达所需几何和预期编辑关系时，优先使用原生参数化草图。同一平面轮廓的线段、圆弧和样条优先直接建为同一个原生草图的几何元素。拉伸或回转直接引用该草图作为截面，尺寸和几何约束集中在草图中编辑，减少特征树中的独立曲线特征。需要单独修改的尺寸保留独立驱动。
- 为草图和特征起能说明部位和用途的名称。例如，草图可称为“尾槽轮廓”，由它生成的减料特征可称为“尾槽切除”，便于在特征树中找到要编辑的对象。使用支持命名的接口写入显示名，程序继续通过逻辑 ID 和会话绑定识别对象。
- 两项特征消费同一设计截面时，对照坐标框架、轮廓定义与驱动来源，再提出共享建议。仅当默认数值相同而设计身份或编辑关系独立时，保留各自驱动。
- 从已确认的等角布局提出圆周阵列候选时，逐项核对种子、实例范围、切深、目标实体、布尔顺序与独立编辑需求，并说明目标 NX 版本对该路线的支持证据。只有布局已确认时，向用户说明尚缺的证据。
- 先展示建议及其编辑影响。改变原有设计关系时须取得相应的意图确认；采用新构造还需目标版本上的几何、编辑与重开证据。原有授权、状态和能力门禁继续适用。

T24.a 实现首版只读建议。T31 的正式产品链验收还应检查：MCP 客户端在建模前能发现并解释适用建议，能识别应保持独立的反例，用户可以继续使用既有方案。

**参数化 P 线**：每个账本项目绑定实际 Driving 约束/特征表达式和使用者，固定/派生项明示；以逐项及关系联动编辑验证实际几何响应，检查允许域边界和越界行为。不能以表达式个数、Fix 全部曲线或参考尺寸充数；不承诺任意拓扑改变成功。

**几何 G 线**：参考 PRT→NX2506 参数 PRT、NX2506→UG11 参数 PRT、参考 PRT→UG11 分别记录。原 STEP 如有仅加溯源检查，不替换已确认参考基准，也不成为必需依赖。

G 覆盖完整实体/所有分区：有效性、连通/占据区域、裁剪边界、解析参数及适用的内核差体/距离检查。面分裂数不同不自动失败；体积、面积、包围盒和有限点采样不能单独证明全域一致。复杂面比较不能完成则 INCONCLUSIVE，阻塞整件验收，不声称制造精度。

容差按参考模型精度、尺度及两版内核能力在 T01 冻结，区分线性/角度/面积/体积和绝对/相对项；不得拿建模器连接容差当制造精度。编辑后按变更后的计划与独立尺寸关系核验，不要求仍等于原始参考形状。

## 7. 分区覆盖与阶段关卡

实际样件账本每行至少包含：来源区域 → 识别/确认依据 → IR/全部参数关系 → NX2506工具及组合证据 → UG11 profile/API → 基准几何证据 → 编辑证据 → 重开/无参考依赖证据。圆角、孔组等若存在也必须有完整行；任一必需行缺失，整件不能验收。

| 阶段 | 唯一归属主任务与推荐顺序 |
| --- | --- |
| P1 参考/能力审计 | T01→T05→T02→T03→T04 |
| P2 IR 与双版本最小贯通 | T06 与 T07 并行；T07 后 T08/T09/T10，T06+T07 后 T11，最后 T12 |
| P3 分区识别/关系与计划 | T13—T17 按文件锁并行→T19 |
| P4 约束与 NX2506 组合 | T18→T20 |
| P5 UG11 编译与脚本包 | T21→T22/T23→T24→T30 |
| P6 分项验收 | T25→T26；T27/T28/T29 按依赖与实机串行执行 |
| P7 整件入口链与交付 | T31→T32 |

一个新主 AI 只负责用户指定的一个 P 阶段，阶段内可组织执行者与独立高级评审的小派单。本阶段评审通过、TL 接收并持久化交接、安全收尾后汇报并结束本轮；下一阶段由用户启动新主 AI，当前不自动派单、开发、测试或准备下一阶段。T25/T26 留 P6，前期只提接口需求；BLOCKED 时仅继续本阶段内独立工作，中断接手须续原阶段，不跳阶段。

主表依赖为最低前置，未知样件缺口 Txx.a 必须在状态台账绑定所属阶段、唯一所有者及后续能力门禁；32 项不是任意样件全部工作量的保证。子任务不反向依赖最终整件验收，SI 检查无环；审计/规划任务完成不代表其中未关闭能力已可执行。

有效证据按测试 ID、代码/输入/环境版本、命令与 cwd、结果路径直接继承，不因换 AI 或换阶段重跑。只有相关变更、证据缺失/不适用或新问题才记录理由并最小复验；不同 NX 版本的首次验证各有证据。T31 是必要的首次整件产品链验收，不重复全部分项矩阵。

不承诺固定工期。若几何分析、设计意图或必需几何/API路线存在未解决项，在台账保留明确阻塞与下一步，不把完整目标改成“先交简单件就算完成”。

## 8. 多 AI、实机纪律与完成定义

- TL 总协调及最终验收；SI 领导软件、合同与共享入口。执行默认 `gpt-6.1-terra` / `xhigh`，或记录的同等执行模型；本轮高级 AI 起草不属于普通执行默认。
- 高级模型（如 `gpt-6-astra`）负责独立评审，平时不接普通实现；实现与审查为不同实例。多评审先独立提交再由 TL 汇总；模型不可用须记录并选可用高级模型。
- 明确阻塞、同类修复两次失败、架构/API冲突才携最小复现、证据、尝试及影响文件升级；高级模型若改实现，仍由另一高级实例独立评审。
- 总并发含主代理不超过 7；建议 TL+SI+2执行+TV+高级评审＝6，留1席。离线按文件锁并行，实机全局串行。
- 无 Git、无 hash 协作：登记文件锁、私有源码快照编号/路径/版本及改动记录，冻结合同后并行；不把时间/大小元数据当内容证明，不覆盖他人变化。既有 NX revision 凭据按接口使用，不扩展为文件散列流程。
- TV 管理唯一实机排队与证据；TL/root 统一启动操作，或明确批准一个执行通道。NX2506、UG11、Journal/helper 同一时刻仅一项实机任务；外部 UG11 脚本显式预约，不假设 F22 gate 自动保护。
- 仅使用用户授权的独立测试件/副本；参考只读，输出冲突停止。不得热替换 DLL、强杀 NX或自行另启会话；更新前正常保存并退出相关进程。
- UNKNOWN/停写立即停后续写入，不重放、不自动解冻；人工核查进程、模型和外部副作用。Tag、ownership、revision、操作凭据不跨会话复用，不在交付物携令牌/私有配置。

状态只由 TL 写入 V3-state：`TODO → READY → RUNNING → REVIEW → DONE`；需改为 `CHANGES`，缺环境/依赖为 `BLOCKED`。READY 要求依赖、范围、接口及文件锁就绪；实机另需环境已确认可用与队列。持续授权仅用于当前指定 P 阶段，新 AI 接手不重问既有常规授权，也不以此自动跨阶段；UG/NX 许可处理授权见续做规则，优先使用电脑现有许可。

**DONE**：本任务交付物及本任务负责的验收/P/G证据齐全且可复现，另一高级实例评审接受，TL 登记验收。前置任务不等待 T27—T31 全件验证才 DONE；完整覆盖矩阵用于宣布样件支持与最终交付。代码完成但任务要求的 UG11 实机证据缺失仍待验证，不能宣称兼容。
