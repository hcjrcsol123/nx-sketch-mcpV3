# V3 分阶段续做规则

版本 1，2026-11-08。本轮仅文档规划；以下授权适用于后续正式开发，不表示本轮已启动开发。目标及 32 项任务以 [开发清单](V3-development-checklist.md) 为准，进度唯一来源为 [V3-state](V3-state.md)。

## 1. 新 AI 从文件接手

读取顺序：适用的工作区/项目 AGENTS.md → 开发清单 → 本规则 → V3-state → 当前任务必要源码/已有证据。不得依赖聊天记录、旧代理 ID 或会话 Tag；本规则不取代更严格的用户禁令。
V3-state 集中保存阶段摘要、任务状态、当前交接、锁/实机队列、证据链接及下一动作；不另建每阶段 handoff、空清单或重复状态表。大量证据由测试自身产物承载，只在 state 链接。
用户启动的新主 AI 先只读核对指定 P 阶段、任务/依赖/锁/风险与可用证据，再在该阶段内继续；不新增“接手演练”，不因换 AI 重新验收有效证据。原阶段中断或 BLOCKED 未完成时，接手者继续原阶段未完成项，不标 DONE 或跳阶段。

## 2. 持续授权及禁止事项

后续正式开发已授权：项目内源码/文档/测试修改、按依赖拆分及并行派单、构建/调试/离线测试、局部可回滚环境配置、可信官方普通开发依赖在项目隔离环境下载使用。
也已授权：参考 `tests/外球叉.prt` 只读分析，使用独立副本/生成夹具，在实际可运行的已安装 NX 中串行测试；保持参考不变及输出独立。常规授权仅供主 AI 在用户指定的当前 P 阶段内执行，无须重复询问；完成该阶段后结束本轮，下一阶段由用户启动新的主 AI，广泛授权不允许自动跨阶段。
- 不自行关机、重启或改变系统会话；不开放公网监听、端口转发、公开隧道或关闭防护，不自动上传私有 PRT、密钥或本地配置。
- 不下载类似本 MCP 的 AI 建模工具；不自行支付或下单；不擅自安装/升级新的 UG/NX，包括为 UG11 测试自行补装。
- 不安全/来源不明文件先说明来源、用途和风险，不静默下载或运行；已知恶意文件默认拒绝并选择可信方案。普通依赖授权不涵盖前两项禁令。
- 本轮及后续均不执行任何 Git 命令，不计算文件、目录或模型 hash；用户广泛授权未取消这些明确禁令。
用户授权：允许使用电脑现有 UG/NX 许可，也允许绕过许可限制；优先使用现有许可。此记录仅表示用户授权，不证明环境可用或任何方式已成功，也不扩展到其他软件或服务。本轮仅记录，不处理许可；正式开发如需处理，仍受不擅装新 UG/NX、不付费、不暴露公网、风险下载先告知等禁令约束。实机验证须有真实执行证据，保留 T06 的真实许可状态记录；环境仍无法运行则记录 BLOCKED，只继续本阶段内无依赖工作。

## 3. 单一状态与必要检查点

正式开发期间只有 TL 写 V3-state；其他代理交付变更请求，由 TL 核对台账修订号后递增更新。SI 协调代码单写者，锁记录任务、文件/模块、责任角色、接管条件；不得用台账版本号代替内容核实。
任务状态为 TODO/READY/RUNNING/REVIEW/CHANGES/BLOCKED/DONE；阶段使用同一组状态。派单需依赖/接口/锁就绪，独立高级评审接受且 TL 接收后才能 DONE；纯规划任务可记录能力缺口后完成，不倒等最终整件验收。
任务结束、中断前、实际风险副作用前后及 UNKNOWN 时更新检查点：已完成/未完成、变更文件、作用对象/输出、结果或不确定性、证据、锁/队列及下一动作。普通只读/离线小步骤不逐步填表。
检查点不含令牌/ownership等秘密；运行上下文不足时停止写操作，不能因未记录“成功”就重做。私有源码快照用编号、路径、代码/接口版本和改动记录管理，不生成散列；时间/大小等元数据不是内容一致证明。

## 4. 七阶段：唯一归属与接续条件

一个新主 AI 只协调用户指定的一个 P 阶段，可在阶段内组织多个执行者及独立高级评审的小任务；仅完成本阶段主任务及对应必要子任务，不把整阶段作为一个执行派单。下表“下一 AI”动作仅写入交接，供用户启动的下个主 AI 执行，当前 AI 不提前执行；具体依赖以清单为准。

| 阶段 / 顺序 | 输入 → 输出 | 出口证据 | 交接给下一 AI 的第一步（当前不执行）；本阶段阻塞时独立工作 |
| --- | --- | --- | --- |
| P1：T01→T05→T02→T03→T04 | 指定参考 PRT/用户目标 → 基线、只读库存、选体及能力/缺口记录 | 参考只读与来源/版本未知项有据；工具覆盖、限制及小缺口完整，不宣称缺口已实现 | 读能力记录，准备 T06/T07；NX 不可用时仅整理已知合同/尺寸待确认项，不编造几何 |
| P2：T06 与 T07；T07 后 T08/T09/T10，T06+T07 后 T11，最后 T12 | P1 记录 → IR/参数账本、授权调用薄适配、UG11 profile 与一次烟测 | UG11 实机版本/语言/许可和最小贯通各有有效证据；块体不代替实际样件 | 读冻结 IR 与账本，派 T13—T17；T06 阻塞可做 T07—T10 中独立离线部分，不放行后续实机依赖 |
| P3：T13—T17→T19 | 参考库存/IR → 主体、增料、减料、关系、过渡的计划及覆盖账 | 每区域有来源、参数和确认；缺口逐项绑定能力门禁，未覆盖不标可执行 | 读计划及约束需求，派 T18；某区域阻塞时继续无依赖区域的小模式，保留整件阻塞 |
| P4：T18→T20 | P3 计划/既有调用层 → 约束绑定和 NX2506 组合 | 本阶段所需缺口关闭，参数及组合/保全门控证据齐全，SI 增量授权接线已完成 | 读已绑定约束和版本映射，派 T21；单模式阻塞时继续不受影响的约束/离线合同 |

| P6：T25→T26；T27/T28/T29 | 双版本输出与有效证据 → 几何、参数编辑、持久性/无源依赖、失败处理证据 | 各任务所需证据无遗漏/未解释失败，有限采样不冒充全域；原有有效证据直接引用 | 读未覆盖项及证据适用版本，准备 T31；某实机项阻塞时处理独立比较器/失败分析 |
| P7：T31→T32 | 全部必需能力/实际包 → 自动产品入口整件链及最终交接 | 真实样件的首次产品链、三段 G/双端 P/持久性证据成立；高级评审接受、TL 接收 | 读最终使用步骤/限制；若阻塞，定位受影响最小子任务，不重跑全部分项矩阵 |

T25/T26 留在 P6，前期仅记录接口需求，不提前开发、测试或准备下一阶段任务。Txx.a 在 state 登记所属阶段、文件所有者及能力门禁，不假装 32 项覆盖任意样件全部工作。阶段出口需本阶段必需任务/子任务证据成立、高级独立评审与 TL 接收；后续缺口保留门禁，复用已有评审，不重复审同一证据。
本阶段评审接受且 TL 接收后，持久化 state 的证据/接口版本/锁与队列/下一阶段第一动作，正常安全归还并收尾自己受控的操作，再汇报、结束本轮；不强杀、不关闭他人程序、不关机，禁止自动派单、编码、测试或准备下一阶段。BLOCKED 时只继续本阶段内独立工作；中断时记录原因、已试方案和下一步，留给新 AI 继续原阶段。

## 5. 证据一次有效使用

每个必需验收只保留一次适用证据：测试 ID、代码/输入/环境版本（含快照编号及输入规格）、准确命令与 cwd、结果/路径和限制。证据离线可访问；私有模型/秘密不写入公开文档。证据缺失或不适用不得通过。
不同 NX 版本的首次测试属于不同证据；T31 首次整件产品链也不是重复分项矩阵。换阶段、换 AI、同内容重新阅读均不是重测理由。
仅相关改动、证据缺失/不适用或新问题触发最小影响复验，先记原因及影响范围；入口改动只重验受影响链路。只需同一运行即可证明的检查共享一次产物，不再启动第二次相同测试。

## 6. 中断、失联与实机恢复

先只读核实可见活动代理、进程/文件占用及改动记录；台账遗留 RUNNING 不证明运行仍在，也不证明已停。仍活动不得抢锁；陈旧锁由 TL 依据核查证据登记接管，不能直接删锁、重放写操作或清 UNKNOWN。
NX2506/UG11/Journal/helper 共用唯一实机队列；TV 预约收证，TL/root 操作或明确指定唯一通道。新 AI 重新获取当前 ownership/binding/revision，不复制旧凭据、Tag 或会话引用。
UNKNOWN 停止后续写入，人工核查进程、模型及外部副作用，不自动重放/解冻；不强杀 NX、不热换 DLL，按既有流程安全归还。遗留不确定写操作先恢复可解释状态，仅本阶段内独立离线工作可继续。

## 7. 精简交接字段与职责

在 state 更新任务状态及长期“证据/评审引用”行，保存测试 ID、代码/输入/环境版本、命令/cwd、结果路径和评审结论的链接或简记；已完成任务和未关闭问题的引用不得随交接删除。当前交接栏可覆盖更新：下一任务、输入/改动、风险/失败尝试、锁/实机状态及下一命令；尚无命令时说明缺项，不编造。
TL 总协调/验收，SI 负责软件/合同/共享入口单写。执行默认 `gpt-6.1-terra` / `xhigh` 或记录的同等模型；独立高级评审（如 `gpt-6-astra`）与实现不同实例，多评审先独立提交。高级改实现仍需另一高级实例审查。
明确阻塞、同类修复两次失败、架构/API冲突时附最小复现、证据及尝试升级；高级平时不接普通实现。总并发含主代理不超过 7，建议 TL+SI+2执行+TV+评审＝6；离线按文件锁并行、实机始终串行。
